# v0.1.0 Report

## Sprints

| # | Name | Scope | Tests |
|---|------|-------|-------|
| 1 | Foundation | Cargo.toml, config types, loading, validation | 13 |
| 2 | Transport | API client, FS writer, dispatcher with auto-fallback | 34 |
| 3 | Output Pipeline | Frontmatter generation, template rendering, write orchestration | 59 |
| 4 | Data Fetching | Cache layer, dynamic select 3-tier fallback | 66 |
| 5 | TUI | App state, dashboard/form/summary screens, event handling | 73 |
| 6 | Integration | Main event loop, CLI arg routing, error handling, panic hook | 80 |

## What Shipped

- Config-driven module system (TOML → typed structs → validated)
- Hybrid transport: API (Obsidian Local REST) with FS fallback
- Two write modes: append (daily note) and create (new file with frontmatter)
- YAML frontmatter + template rendering with strftime and field interpolation
- Dynamic select with 3-tier fallback (API → cache → empty)
- TUI: dashboard → form → summary flow
- CLI fast-path: `pour <module>` skips dashboard
- Panic hook restores terminal cleanly

## Design Decisions

- Synchronous event loop (draw/poll/handle per tick) — async would add complexity without meaningful UX gain for v0.1
- `std::fs::rename` for atomic writes (later found broken on Windows — fixed in v0.2)
- `serde_yaml` initially used, removed in v0.2 prep
- Comma-in-value heuristic splits `", "` into YAML lists — intentional for multi-select, problematic for literal commas

## Not in v0.1

- Background async refresh of dynamic selects
- History pruning
- Configurator TUI
- Undo/confirmation before write
